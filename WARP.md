# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project Overview

This is a TCP/IP stack implementation project written in C. The codebase implements a graph-based network topology simulator with nodes (routers/devices) connected via links (interfaces). It serves as the foundation for building a custom TCP/IP protocol stack.

## Build Commands

### Build the project
```bash
make
```
or
```bash
make all
```

### Clean build artifacts
```bash
make clean
```

### Run the test application
```bash
sh run.sh
```
or directly with the dynamic linker:
```bash
/lib64/ld-linux-x86-64.so.2 ./test.exe
```

Note: If the filesystem is mounted with `noexec`, use one of the above methods instead of `./test.exe`

## Architecture

### Core Components

**Graph Data Structure** (`graph.h`, `graph.c`)
- Foundation of the network topology representation
- `graph_t`: Top-level topology container that holds all nodes
- `node_t`: Represents network devices (routers, switches, hosts) with up to 10 interfaces
- `link_t`: Bidirectional connection between two nodes, each side represented by an `interface_t`
- `interface_t`: Network interface belonging to a node, contains network properties

**Glue Thread Library** (`gluethread/`)
- Custom doubly-linked list implementation for managing graph nodes
- Provides intrusive linked list functionality (similar to Linux kernel lists)
- Key macro: `GLTHREAD_TO_STRUCT()` converts from embedded `glthread_t` to parent struct
- Nodes are linked together via `node_t.graph_glue` field

**Network Properties** (`net.h`, `net.c`)
- `node_net_props_t`: Node-level network configuration (loopback address)
- `intf_nw_props_t`: Interface-level network configuration (MAC address, IP address, subnet mask)
- Provides functions to configure IP addresses on nodes and interfaces

**Topology Builder** (`topologies.c`)
- `build_first_topo()`: Creates sample network topologies for testing
- Current implementation creates a 3-router topology (R0_re, R1_re, R2_re) in a triangle

**Test Application** (`testapp.c`)
- Entry point that builds and displays a test topology

### Key Design Patterns

**Container-of Pattern**: The glthread library uses pointer arithmetic to retrieve the parent structure from an embedded field, allowing efficient list traversal without allocating separate list nodes.

**Intrusive Lists**: Rather than wrapping structs in list nodes, `glthread_t` is embedded directly in structs like `node_t`, reducing memory allocations and indirection.

**Bidirectional Links**: Each `link_t` contains two `interface_t` structs representing both ends of the connection, making neighbor lookup efficient.

### Data Flow

1. Create graph with `create_new_graph()`
2. Add nodes with `create_graph_node()` - nodes are added to graph's linked list
3. Connect nodes with `insert_link_between_two_nodes()` - creates link and assigns interfaces
4. Configure network properties (IP/MAC addresses) via `net.h` functions
5. Traverse/dump topology using glthread iteration macros

## File Organization

- Root: Core graph implementation and main application
- `gluethread/`: Reusable linked list library (originally from github.com/sachinites)
- `obj/`: Build artifacts (generated by make)

## Code Conventions

- Struct typedefs end with `_t` suffix
- Interface access via `node->intf[]` array (max 10 per node)
- Neighbor lookup: `get_nbr_node(interface)` traverses link to opposite interface
- Use `ITERATE_GLTHREAD_BEGIN/END` macros for safe list iteration
